FIREBASE RTDB REFERENCE — Autura Marketplace
Source: reverse-engineered from app.marketplace.autura.com/static/js/main.be109958.js

This document describes all Firebase RTDB paths used by the Autura Marketplace
frontend, including what data lives at each path, how the client subscribes,
and how our Python backend should interpret messages from the REST SSE interface.

--------------------------------------------------------------------------------
1. DATABASE ROOT
--------------------------------------------------------------------------------

    https://digital-auction.firebaseio.com

All paths below are relative to this root.

WebSocket endpoint (browser uses this directly):
    wss://s-gke-usc1-nssi4-67.firebaseio.com/.ws?v=5&ns=digital-auction

Our backend uses the REST SSE interface:
    GET /{path}.json?auth={token}
    Accept: text/event-stream

REST SSE message envelope:
    event: put          <- initial dump (full subtree)
    data: {"path": "/", "data": { ... }}

    event: patch        <- incremental update (merged, not replaced)
    data: {"path": "/some/child", "data": { ... }}

    event: cancel       <- auth revoked or permission denied
    data: null

    event: auth_revoked <- token expired
    data: null

IMPORTANT: The browser SDK uses child_added / child_changed events internally,
but over REST SSE you only get put/patch. A "put" at a child path is equivalent
to a child_added or child_replaced. A null data value means the node was deleted.

2. PATH: /{regionId}/auctions
--------------------------------------------------------------------------------

PURPOSE: Auction lifecycle — status, ended flag, auctionSeries membership.

SUBSCRIPTION (browser):
    subscribeToSnapshot("/{regionId}/auctions", callback)
    // listens with "value" event — gets full map on change

SHAPE (each child keyed by auctionId, e.g. "auction-109555"):
    {
      "auctionId":    "auction-109555",   // sometimes absent (key is the id)
      "regionId":     "NSH-TN",
      "ended":        false,              // TRUE when auction is complete
      "endedAt":      1714000000000,      // epoch ms, present when ended=true
      "auctionSeries": "some-series-key",
      "sellers":      { "JS-225": true },
      "startTime":    1714000000000,      // epoch ms
    }

OUR USAGE:
    - Watch for ended: true  → call handle_auction_completed()
    - Unknown auctionId      → call _trigger_discover_and_scrape()
    - REST SSE path: /{regionId}/auctions.json

3. PATH: /{regionId}/results/{auctionId}/{itemId}
--------------------------------------------------------------------------------

PURPOSE: Timed / pre-auction bids. One child per item, updated as bids arrive.
         This is the PRIMARY bid path for timed auctions.

SUBSCRIPTION (browser):
    path = "/{regionId}/results/{auctionId}"
    subscribeToSnapshot(path, handler, "child_added")
    subscribeToSnapshot(path, handler, "child_changed")

    mapper: Gi = (regionId, auctionId) => snapshot => ({
        ...snapshot.val(),   // the bid object below
        itemId:   snapshot.key,   // e.g. "JS-225-50499"
        regionId: regionId,
        auctionId: auctionId,
    })

BID OBJECT shape (snapshot.val()) — verified from real SA-TX/auction-109498 live capture:
    {
      "amount":      1000,            // current winning bid in dollars (number)
      "uid":         "gnC9MK81l2PFLhvsOi5h5Goekbz2",  // Firebase UID of winning bidder
      "bidId":       "-Orvd8r7G5pqwkiKEolV",           // Firebase push ID of this bid
      "expiration":  "2026-05-06T20:44:50.000Z",        // ISO 8601 — bid timer deadline
      "timestamp":   "2026-05-06T04:56:02.760Z",        // ISO 8601 — when bid was placed
      "start":       "2026-05-05T15:00:00.000Z",        // ISO 8601 — auction start time
      "reservePrice": 0,              // reserve price (0 = no reserve)
      "reserveMet":  true,            // whether reserve has been met
      "isExemptFromSalesTax": false,
      "isUserPreApproved":    false,
      "payInFullAvailable":   true,
      "fees": {
        "bid":                 1000,  // same as amount
        "salePrice":           1000,
        "buyerFee":            0,
        "platformFee":         100,
        "adminFee":            32,
        "variableFee":         0,
        "vehicleKeyFee":       0,
        "vehicleOtherFixedFee": 0,
        "salesTax":            0,
        "storageTax":          0,
        "total":               1132, // buyer's total out-of-pocket
        "totalSellerDue":      1032
      },
      "autobid": {                    // PRESENT when an autobid was outbid by this bid
        "amount":    800,             // the autobid's max amount
        "bidId":     "-Oruai6C02bnCORUZhV5",
        "timestamp": "2026-05-06T00:05:47.598Z",
        "uid":       "BdhvN6vGnWfx4oIRzrDcTkvpCl03"

      // authType and bidInfo are NOT present on /results/ updates (unlike /bids/)
    }

VALIDITY CHECK (from source):
    A bid is valid only if:
        uid != null
        AND typeof amount === "number" AND amount > 0
        AND authType != null

OUR USAGE:
    - REST SSE path: /{regionId}/results/{auctionId}.json
    - On each child update: UPDATE vehicles SET current_bid = amount,
      bid_expiration = expiration WHERE item_key = itemId
    - Broadcast {"type": "bid", "item_key": itemId, "amount": amount}
    - Unknown itemId → trigger rescrape (with _rescrape_attempted guard)

WEBSOCKET UPDATE ENVELOPE (confirmed from live capture):
    Server pushes bids as action "d" (data) with this structure:
        {
          "t": "d",
          "d": {
            "b": {
              "p": "SA-TX/results/auction-109498/438-8999580",  // NOTE: no leading /
              "d": { ...full bid object... }
            },
            "a": "d"   // "d" = server-pushed data (not a response to a request)
          }
        }

    IMPORTANT: The path has NO leading slash in WebSocket push messages.
    Our REST SSE interface always has a leading slash — this is a WebSocket-only quirk.

REST SSE MESSAGE SHAPES for this path:

    Initial dump (event: put, path: "/"):
        data: {
          "path": "/",
          "data": {
            "JS-225-50499": { "amount": 5000, "uid": "...", "expiration": "...", ... },
            "JS-225-50500": { "amount": 3200, ... },
            ...
          }
        }

    Single item update (confirmed from live capture — full object replacement):
        data: {
          "path": "/438-8999580",
          "data": { "amount": 1000, "uid": "...", "expiration": "...", "fees": {...}, ... }
        }
        → Full bid object is sent every time, not just changed fields.

    Single field update (less common):
        data: {
          "path": "/JS-225-50499/amount",
          "data": 5500
        }

    Item with no bids yet:
        data: { "path": "/JS-225-50499", "data": null }   (deleted/absent)

4. PATH: /{regionId}/items/{auctionId}/{itemId}
--------------------------------------------------------------------------------

PURPOSE: Full item state including live auctioneer bids (currentResult).
         When an auctioneer is actively calling the car live, bids route here,
         NOT to /results/. This path ALSO holds all item metadata.

SUBSCRIPTION (browser):

    subscribeToSnapshot(ref, callback)   // "value" event — full list

    Each snapshot child:
        {
          ...item.val(),    // full item object (see ITEM OBJECT below)
          key:      snapshot.key,   // item_key, e.g. "JS-225-50499"
          regionId: regionId,
          auctionId: auctionId,
        }

    Single item replaced (path: "/{itemId}"):
        data: {
          "path": "/JS-225-50499",
          "data": { "idx": 0, "currentResult": { "amount": 5000, ... }, ... }
        }

    currentResult replaced (path: "/{itemId}/currentResult"):
        data: {
          "path": "/JS-225-50499/currentResult",
          "data": { "amount": 5500, "uid": "...", "expiration": "...", ... }

    Single field in currentResult (path: "/{itemId}/currentResult/amount"):

    - Only care about currentResult updates: extract amount, expiration
    - UPDATE vehicles SET current_bid = amount, bid_expiration = expiration
      WHERE item_key = itemId
    - Broadcast {"type": "bid", "item_key": itemId, "amount": amount}
    - Optionally watch status → "sold" to trigger harvest

9. LIVE vs TIMED AUCTION BID ROUTING SUMMARY
--------------------------------------------------------------------------------

NOTE: Bid updates (amount, expiration, fees) are ONLY visible when subscribed to
a specific auction's stream. The region-level /{regionId}/auctions path carries
lifecycle events only (ended, auctionSeries membership, etc.) — no bid data flows
through it. You must be subscribed to /{regionId}/results/{auctionId} or
/{regionId}/items/{auctionId} to receive bids for that auction.


    TIMED auction (no live auctioneer):
        Bids → /{regionId}/results/{auctionId}/{itemId}
        Path in REST SSE: /{regionId}/results/{auctionId}.json

    LIVE auction (auctioneer calling cars):
        Bids → /{regionId}/items/{auctionId}/{itemId}/currentResult
        Path in REST SSE: /{regionId}/items/{auctionId}.json

    BOTH can be active simultaneously (some items timed, auctioneer on one).
    Our listener MUST subscribe to BOTH paths per auction.

10. PATH PARSING IN PYTHON (REST SSE)
--------------------------------------------------------------------------------

When we receive a message on /{regionId}/results/{auctionId}.json:

    data = json.loads(payload)
    path  = data["path"]   # e.g. "/" or "/JS-225-50499" or "/JS-225-50499/amount"
    inner = data["data"]

    parts = [p for p in path.split("/") if p]

    if len(parts) == 0:                      # initial full dump: path == "/"
        # inner is dict of itemId -> bid_obj
        for item_id, bid_obj in (inner or {}).items():
            amount = bid_obj.get("amount")
            expiration = bid_obj.get("expiration")

    elif len(parts) == 1:                    # single item replaced
        item_id = parts[0]
        if isinstance(inner, dict):
            amount = inner.get("amount")
            expiration = inner.get("expiration")
        elif inner is None:
            pass  # item deleted / no bid

    elif len(parts) == 2 and parts[1] == "amount":
        item_id = parts[0]
        amount = inner                       # scalar int/float

    elif len(parts) == 2 and parts[1] == "expiration":
        item_id = parts[0]
        expiration = inner

    # other field paths (uid, fees, bidInfo) — ignore


When we receive a message on /{regionId}/items/{auctionId}.json:

    parts = [p for p in path.split("/") if p]

    if len(parts) == 0:                      # initial dump — SKIP (too large)
        continue

    elif len(parts) == 1:                    # full item replaced
        item_id = parts[0]
        if isinstance(inner, dict):
            cr = inner.get("currentResult")
            if isinstance(cr, dict):
                amount = cr.get("amount")
                expiration = cr.get("expiration")

    elif len(parts) == 2 and parts[1] == "currentResult":
        item_id = parts[0]
        if isinstance(inner, dict):          # currentResult object set/replaced
            amount = inner.get("amount")
            expiration = inner.get("expiration")
        elif inner is None:                  # currentResult cleared (car sold/moved)
            pass

    elif len(parts) >= 3 and parts[1] == "currentResult" and parts[2] == "amount":
        item_id = parts[0]
        amount = inner                       # scalar

    elif len(parts) >= 3 and parts[1] == "currentResult" and parts[2] == "expiration":
        item_id = parts[0]
        expiration = inner

    elif len(parts) == 2 and parts[1] == "status":
        item_id = parts[0]
        status = inner                       # "sold", "unsold", etc.
        # Could trigger harvest if status == "sold"

    # other field updates — ignore

11. OTHER PATHS (browser-only, not needed by backend)
--------------------------------------------------------------------------------

These paths were confirmed via parse_har.py analysis of a captured HAR session and
from Autura's JS bundle (main.be109958.js). The browser subscribes to all of them,
but our backend has no need to watch them. Documented here so nothing is mysterious.

  /globalConfig
      Global feature flags and config values. Shape: flat key→value dict.
      Browser reads once on load. Not region-scoped.

  /regions
      All active auction regions. Already documented in section 8.

  /sellers/{sellerId}
      Seller profile/metadata. Keyed by sellerId (e.g. "JS-225").
      Shape: { name, locationId, ... }

  /platformFeeSchedules
      Fee schedule definitions used to compute buyer fees per tier.
      Shape: nested dict of schedule name → tier → fee object.

  /userRoles/{uid}
      Role flags for a logged-in user (admin, seller, buyer, etc.).
      Shape: { admin: bool, seller: bool, ... }

  /userPreApproved/{uid}
      Pre-approval status per user for specific sellers or auctions.
      Shape: flat bool flags or nested by sellerId.

  /wonItems/{uid}
      Vehicles won by this user across all auctions.
      Shape: dict of itemKey → won item summary.

  /eventSubscriptions/{uid}
      Events (auctions) this user has subscribed/registered for.
      Shape: dict of eventId → bool or subscription metadata.

  /events/transient/{eventId}
      Live event state during a running auction (e.g. currently-on-block item).
      Shape: { currentItemId, status, ... }
      This is likely how the browser knows which car the auctioneer is on.

  /users/{uid}/favorites/{itemKey}
      User's saved/favorited vehicles. Shape: bool or timestamp.

  /{regionId}/biddersNumbers/{auctionId}/{itemId}
      Already documented in section 6b.

  /{regionId}/attributes/{auctionId}
      Filter attribute lookup tables for a specific auction. Confirmed from live capture.
      Contains all possible values for filterable fields, used to populate filter dropdowns.
      Shape:
        {
          "body":      { "4 DOOR": { "originalValue": "4 DOOR" }, "2 DOOR": {...}, ... },
          "color":     { "BLACK": { "originalValue": "BLACK" }, ... },
          "keyStatus": { "NO_KEY": { "originalValue": "NO_KEY" } },
          "make":      { "FORD": { "originalValue": "FORD" }, ... },
          "model":     { "FORD": { "F150": { "originalValue": "F150" }, "originalValue": "FORD" }, ... },
          "year":      { "2020": { "originalValue": 2020 }, ... }
        }
      NOTE: model is nested make → model → {originalValue}. Year originalValue is a number.
      Browser subscribes once per auction load, unsubscribes immediately after (action "n").

  /userAnnouncements/{uid}/{regionId}/{auctionId}/dateClosed
      Per-user dismissal timestamp for auction announcements/notifications.
      Browser writes to this path (action "n") when user closes an announcement.
      Shape: scalar string (ISO date) or null.

  /GoogleDrive/queue
      Internal upload queue for Google Drive integrations. Irrelevant.

  capture, (b) JS bundle reverse-engineering of main.be109958.js ref() calls.

- item_key in our DB == itemId in Firebase == snapshot.key in the results path.
  Example: "JS-225-50499" (format: {sellerId}-{numeric})

- Firebase REST SSE sends event: put for initial state and full replacements,
  event: patch for partial updates (merged into existing node).
  Our Python listener does not need to distinguish — both carry path+data.

- Token expires every ~1 hour. The stream will send event: auth_revoked or
  simply disconnect. Always reconnect with a fresh token.

- The items path initial dump is large (full vehicle info for every lot).
  Always skip it — the results path provides current bid state on connect.

- A null data value at any path means that node was deleted from RTDB.
  For bids: item has no current bid. For currentResult: car is off the block.
